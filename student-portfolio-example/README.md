# 학생 포트폴리오 완성 예시

이 폴더는 GitHub Pages에 그대로 배포할 수 있는 정적 웹사이트입니다. 별도의 설치나 빌드 과정이 필요하지 않습니다.

## 파일 구성

- `index.html`: 자기소개와 프로젝트 내용
- `style.css`: 색상, 레이아웃, 모바일 화면
- `script.js`: 화면에 들어올 때 한 번만 살짝 떠오르는 효과(동작 줄이기 설정 시 자동 해제)
- `resume.pdf`: 첫 화면의 "이력서 보기" 버튼이 여는 이력서(본인 PDF를 같은 이름으로 교체)
- `images/`: 프로젝트 캡처 이미지(같은 파일명으로 교체)

디자인은 `DESIGN.md`(Refero Styles의 Ventriloc)의 색, 글꼴, 간격, 컴포넌트 규칙을 따릅니다. 타자 효과, 스크롤 진행 바, 큰 그림자, 다크 모드처럼 템플릿스러운 장식은 제거했고, 주황색(Ember Orange)은 링크 밑줄과 작은 강조에만 사용합니다.

헤딩 글꼴 PolySans는 상용 글꼴이라 무료 대체 글꼴인 Inter Tight(weight 400)를 사용했고, 한글은 Pretendard로 표시됩니다.

## 학생이 반드시 바꿀 내용

1. 이름과 지원 직무
2. 한 줄 자기소개
3. 대표 프로젝트 2~3개
4. 프로젝트별 문제, 본인 기여, 결과
5. 이메일과 GitHub 주소
6. 졸업 예정일과 구직 상태

성과 수치를 만들기 위해 사실이 아닌 숫자를 쓰지 않습니다. 수치가 없다면 `테스트 12개 작성`, `데이터 3,200건 정제`, `팀원 4명 중 API 담당`처럼 확인 가능한 범위를 적습니다.

## 로컬에서 확인하기

`index.html` 파일을 브라우저로 열면 됩니다. 일부 브라우저에서 저장 기능을 정확히 확인하려면 간단한 로컬 서버를 사용합니다.

```powershell
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`에 접속합니다.

## GitHub Pages 배포

1. GitHub에서 `사용자이름.github.io`라는 공개 저장소를 만듭니다.
2. 이 폴더의 파일을 저장소 최상위에 업로드합니다.
3. 저장소의 `Settings`에서 `Pages`를 선택합니다.
4. 배포 소스를 `Deploy from a branch`, 브랜치를 `main`, 폴더를 `/root`로 지정합니다.
5. 잠시 후 `https://사용자이름.github.io`에서 확인합니다.

## 제출 전 확인

- 모바일에서도 가로 스크롤이 생기지 않는가
- 첫 화면에서 지원 직무가 보이는가
- 프로젝트마다 본인 역할이 적혀 있는가
- 이메일과 GitHub 링크가 실제 주소인가
- 맞춤법과 개인정보 공개 범위를 확인했는가
